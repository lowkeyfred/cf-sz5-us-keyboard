# 方法学：把这套流程搬到别的机型

本文提炼 CF-SZ5 项目里**可迁移**的部分。固件机制定案见
[FINDINGS.md](FINDINGS.md)。

## 整体流程

1. **获取原始镜像**：官方更新程序通常把固件作为 PE 资源携带（CF-SZ5 在
   resource 10/3003/1033），胶囊格式 `[u32 crc32(解压镜像)][u32 未压缩大小]
   [LZNT1 块]`。`scripts/extract_firmware.py` 演示了提取过程。
2. **定位键盘映射表**：EC 代码通常是 ARC（ARCompact）或 8051 内核。搜索
   键盘扫描循环里的 `raw & 0x7F`（矩阵行/列去位）和随后的表查找。CF-SZ5 的
   E 表在固件偏移 0x2969C，128 字节，每项是一个 set-2 码（0xFF=空）。
3. **理解处理链**：E 表值不是直接发出的——CF-SZ5 里 0xFF 丢弃、0x96 特殊、
   0xC0-0xDF 走 T7128 双字节表、0xE0-0xFF 查每键 CT1'/CT2' 表，≥0x80 的码
   再查 slot 表分发到处理函数，最后由 8042 从 set-2 翻成 set-1。
   **改映射前先静态走通这条链**，否则你会把 Pause/E0 前缀码当成普通码发出。
4. **实机定位错位键（探针法）**：构建一个探针固件，把所有空闲 E 表位接上
   互不相同的字母/数字标记（set-2 <0x80，经 8042 翻译后肉眼可读）。实机按
   错位键 → 终端显示标记字母 → 反推矩阵位置。`scripts/build_diag2.py` 是
   现成实现。

## 奇偶校验陷阱（本项目最贵的教训）

矩阵扫描码通常 7 位有效 + 1 位奇偶/状态。探针固件若用 `raw >> 1` 之类手段
腾挪代码空间，会**摧毁奇偶位**——诊断索引 k 对应 raw 2k 和 2k+1 两个候选。
本项目最早的补丁曾把同一索引的两个奇偶位全改，一次干掉了 6 个本来正常的键，
靠全键扫描里的"双发"指纹才定位到——这是本项目交过学费的一课。

**规则：永远不要对两个候选位置一起打补丁。先查原始 E 表里每个候选位置的值：
另一个奇偶位若是活键（比如 CF-SZ5 的 0x3F = LShift，stock 0x12），它必须保持
原值。** 只补空的那个。

诊断后可以用同一指纹复核：按物理顺序全键扫一遍，任何输出码出现两次 = 还有
奇偶位被误伤。

## 完整性不变量（CF-SZ5 实测，其他机型需自行验证）

- `u16 @0x218 == crc24(镜像)`：init 0x00FFFF，跳过 0x200-0x27F，
  每字节 8 次 `<<=1; if bit24 ^= 0x01102100`。
- `sum(全镜像) & 0xFFFF == u16 @0x20A`（L19 = 0xA88D），即除 0x20A/0x20B
  外所有字节之和 ≡ 0 (mod 2^16)。
- `fix_crc_sum.py` 的修法：0x2B453-0x307FF 是大片无引用的 0xFF 填充区，
  先粗调（整字节压值利用 mod 2^16 回绕），再在 ±500 带内扫描"单位置 × 全
  256 值"精确命中。**先用静态反汇编确认填充区在你目标机型上同样无引用。**

## 更新程序重打包

- 胶囊头 dword0 = CRC-32/BZIP2（多项式 0x04C11DB7，init/xorout 0xFFFFFFFF，
  MSB-first）的解压后镜像。
- 版本门：INI 资源（CF-SZ5 为 resource 10/3000/1033，自定义混淆格式）里
  `SameVersionPolicy` 默认拒绝同版本刷写；重打包时改成 0。
- CF-SZ5 实测：完整 Windows 直接刷写成功（多轮验证）；WinPE 反而失败；VM/Wine 被拒。刷完重启。
- PE 数字签名在修改后必然失效：清空证书表、裁剪 overlay、重算 PE checksum
  （`build_ecupdate2.py` 的 `pe_checksum`）。

## 安全

- 先构建**恢复版**更新程序（原始镜像 + SameVersionPolicy=0）并验证它能运行。
- 探针固件会破坏正常键盘输出，只在诊断时用，用完立刻刷回。
- 绝不在 VM/Wine 里刷 EC；绝不写 EC RAM；没有备份不刷机。
